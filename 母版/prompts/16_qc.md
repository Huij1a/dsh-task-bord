# 16 质检（分卷交叉判定）

## 任务

做交付前交叉检查，决定当前版本能否进入 17 打包。读取范围严格取 `artifacts/14_score/汇总.json.run_ids`：默认只有 `C01`，最多为 `C01/C02`；必须逐卷核对评分、隔离审计、外部题包输入、host trace、13 归档和 15 读卷，再核对最终选卷。**只读，不改任何题包、答卷、评分、读卷或考点。**

## 检查项

| ID | required | 检查 | 通过条件 |
|---|---|---|---|
| ELEMENTS | true | 入包要素 | 最终题面、交付规格、字段映射/差量、A 系列与附件事实快照、B 系列与 B 索引、rubric、rules.py（如有）、人工复核（如有 manual）、难点覆盖、答案核验、作答思路、易错点、校验结论均存在且非空；`校验结论.json.pass=true` 且 `required_check_ids` 恰好覆盖其固定 14 项一次 |
| VERSION | true | 版本一致 | 冻结清单的 question/expert/model_input 三类文件均存在且 `bytes`、`sha256` 与磁盘一致；模型输入只读 frozen 副本；`校验结论.json.upstream_hashes` 的六项摘要均与冻结清单重算值一致，B 索引中的 `OUTxx` 均能在 04 找到 |
| ISOLATION | true | 逐卷输入与审计 | `run_ids` 仅含 `C01` 或 `C01/C02`，各卷均有评分报告和外部题包；`runs[].answer_package` 逐卷严格为 `D:\高经作答区\<taskId>\<runId>` 并位于 `taskDir` 外。每卷核对 `artifacts/13_answer/<runId>/隔离审计.json` 和题包根 `host_trace.json`：存在的文件必须身份正确，逐卷重算 trace SHA-256 并与该卷评分报告 `run.host_trace_sha256` 比对；缺失文件只能作为未选中无效卷的明确失败证据，不能记作已核验。审计中的输入清单必须可复核。所选卷的 `input/` 必须逐文件与冻结 `model_input_files` 的 `path/bytes/sha256` 完全一致且无额外文件，六项 check 全 pass、`violations=[]`、trace 7 必需字段和 `source=host` 均有效、状态为 `verified`。未选中的无效卷必须由 14 明确标为 `valid=false`/不得通过，并原样保留失败证据；其无效理由必须与审计/trace/评分记录一致，不得被误当作低分有效卷参与选卷 |
| UPSTREAM | true | 上游判定 | 07 `pass=true`；10 `pass=true` 且 `route=null`；11 `校验结论.json.pass=true` 且含 manual 时 `checks[check_id="manual_items"].status=pass`；14 `汇总.json.pass=true`、`selected_run_id` 非空，所选卷 `评分.json.difficulty_pass=true` 且 `pass=true`，15 `汇总.json.selected_run_id` 与 14 完全相同且每卷读卷齐全。只引用，不重算 |
| SPEC | true | 规格闭合 | 04 的每个 deliverable/part/business field 均能回指题面与 08/09 映射；11 每条 rubric 的 `difficulty_id` 在 05 中真实存在且被 `难点覆盖.json` 计入，withdrawn 项必须有理由并仅进入 withdrawn 列表，`complete=true` 且 `uncovered_difficulties=[]`；11 每条坐标和 `business_field_keys` 能回指 04；B 索引引用真实 `OUTxx`；15 的每个考点 ID 在 rubric 中存在 |
| GATE | true | 项目约束 | `task_types`、`industry_tree`、`occupation_tree`、`forbidden`、`deadlines`、`quality_gates`、`attachment_policy` 按 `extraction_status` 核验；`null + not_applicable` 是不适用，`unparseable`/`conflict` 阻断，不得补默认值 |

| QUALITY | true | AI 痕迹与同质化 | 对最终题面、A 系列、B 系列、rubric、作答思路逐层检查模板化/AI 痕迹、异常同构表达和不自然重复；门槛 `history_refs` 非 `null + extracted` 时至少比较结构、任务链、数据分布、答案路径中的两个独立维度并记录差异；`history_refs=null + not_applicable` 时把历史比较记为 `not_applicable`，不阻断本 check；若 `history_refs` 已声明但样本不可读，记 `not_verifiable` 并阻断，不得伪写 pass |

## 输出

只写一个 UTF-8 JSON 文件：`artifacts/16_qc/结论.json`。

```json
{
  "schema_version": 1,
  "run_ids": ["C01"],
  "selected_run_id": "C01|null",
  "runs": [
    {
      "run_id": "C01",
      "answer_package": "D:\\高经作答区\\<taskId>\\C01",
      "score_report": "artifacts/14_score/C01/评分.json",
      "isolation_audit": "artifacts/13_answer/C01/隔离审计.json",
      "host_trace": "D:\\高经作答区\\<taskId>\\C01\\host_trace.json",
      "review_record": "artifacts/15_review/C01/读卷记录.json",
      "difficulty_pass": true,
      "pass": true,
      "isolation_pass": true,
      "host_trace_status": "verified",
      "valid": true,
      "selected": true
    }
  ],
  "pass": false,
  "checks": [
    {
      "check_id": "ELEMENTS",
      "required": true,
      "status": "pass|fail|not_applicable|not_verifiable",
      "evidence": ["artifacts/11_rubric/校验结论.json#pass=true"],
      "detail": "实际核对结果"
    }
  ],
  "findings": [
    {
      "finding_id": "F01",
      "check_id": "VERSION",
      "severity": "blocking|warning",
      "path": "artifacts/12_freeze/冻结清单.json",
      "pointer": "/files/0/sha256",
      "message": "具体、可复核的问题",
      "route": "00|04|05|06|08|09|11|12|13|14|15"
    }
  ],
  "summary": "一句话说明能否进入 17，以及阻断项数量"

```

字段规则：

- `run_ids`、`selected_run_id` 必须与 `artifacts/14_score/汇总.json` 深等；只允许 `["C01"]` 或 `["C01","C02"]`。`runs[]` 按 `run_ids` 原序逐卷出现且各一次，禁止第三卷、重复卷或从目录自行臆造卷号。
- `runs[].answer_package` 必须是 14 汇总中的原值；`isolation_audit` 固定指向本卷归档根，`host_trace` 固定指向外部题包根。未选中的无效卷仍保留在 `runs[]`，`selected=false` 并如实记录其状态，但不得影响所选有效卷的通过条件。
- 八个 `check_id`（ELEMENTS/VERSION/ISOLATION/UPSTREAM/SPEC/GATE/LEAKAGE/QUALITY）必须全部出现且各一次；新版本不得省略 `LEAKAGE` 或 `QUALITY`。任何依赖分卷证据的 check，其 `evidence` 都必须覆盖 `run_ids` 的每个卷；`ISOLATION` 和 `UPSTREAM` 的 detail 还必须分别写出所选卷 `isolation_pass=true` 和 `host_trace_status=verified`。
- `校验结论.json` 的 `required_check_ids` 必须恰好覆盖 11 规定的 14 项且各一次；缺失、重复或未知 check 均判 `VERSION=fail`。
- `人工复核.json` 存在时，其 `rubric_sha256` 必须与冻结 rubric 一致，manual R ID 集合必须一一对应；缺项、多项或状态非 `pass` 均阻断。
- `pass=true` 仅当所有 `required=true` check 的 `status=pass`，且 `findings` 中没有 `severity=blocking`；任一 required check 为 `fail`、`not_applicable` 或 `not_verifiable` 都会阻断。
- 每个 check 必须有至少一条实际 `evidence`；只写“已检查”不算证据。QUALITY 的 evidence 必须同时列出逐层扫描文件、检测方法、实际命中或“未命中”的可复核结果；`history_refs` 已声明时还须列出实际历史样本路径，未声明时明确写历史比较 `not_applicable` 及对应提取依据。
- `not_applicable` 只能用于规范确实未写的可选约束，且 evidence 必须指向 `extraction_status` 的 `not_applicable`；核心文件和上游判定不得标 NA。`not_verifiable` 只用于门槛已声明 `history_refs` 但样本不可读，或无法执行必要的质量比对；必须写清缺失对象，不能等同通过。`history_refs=null + not_applicable` 只使历史比较子项不适用，仍须完成 AI 痕迹检查并据实判定 `QUALITY`。
- `findings=[]` 表示无问题；有问题时每项必须含稳定 ID、路径和 pointer、具体差异及唯一返修主责。
- `summary` 写结论和阻断项数量，不复述整张检查表。

最终回复最后一行必须是与文件顶层相同的单行 JSON，且 `run_ids/selected_run_id/runs/pass/checks/findings/summary` 深等。调用方无法解析时按不通过处理。

## 返修路由

- 门槛来源、行业/职业树、可选门槛状态 → `00`
- 业务字段、交付坐标、单位/精度/容差 → `04`
- 难点、附件业务字段登记 → `05`
- 附件事实或格式 → `06`
- 题面转写、字段映射 → `08`
- 最终题面润色、映射差量 → `09`
- 考点、标答、覆盖或机器校验结论 → `11`
- 冻结范围、同版 hash、隔离输入 → `12`
- 答卷缺失或内容、当前卷归档缺失 → `13`
- 既有评分结论、选卷或运行指标 → `14`
- 15 读卷缺失、分卷遗漏或跨卷汇总不一致 → `15`

17 尚未运行，不得把 17 作为返修节点；若仅缺包成员，`pass=false`，由编排在 17 后另行核对。

## 禁止

- 不修改任何被检查文件。
- 不重算 07/10/11/14 的业务判定。
- 不把 `platform_fields` 当作题目业务字段，也不要求 04 复制平台栏位。
- 不因 `warning` 判失败，不隐瞒任何 `blocking`。
- 不把 `null + not_applicable` 误报为缺失。

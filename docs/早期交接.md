## 已知问题（按优先级）

### P1 交付结构必须写进题面，不能只写在节点提示词里

模型这次用了自己的 sheet 命名（封面 / 输入清单 / 去重与撤回 / 截止点快照 / 案件终态矩阵 / 逐案责任 / 品牌执行排程 / 资源约束 / 准备金与现金 / R04恢复边界 / 公式与口径 / 跨文件对账），没有按 13_answer.md 里给的「决策摘要 / 案件裁定 / 五时点沿革 / R04恢复边界 / 品牌执行排程 / 约束检查」。

后果：本地判定器 34/100，其中 **17 项 MISSING 全是结构不匹配**，不是算错。

**修法**：把交付物结构（sheet 名、列名、文件名）写进 `artifacts/08_prompt/题面.md`，13_answer.md 里只引用"按题面规定"。八期的示范题就是这么做的（"按模板填写，文件名保持一致"）。

### P2 判定器需要结构适配层

`judge.py` 按示范题的 sheet/字段名取数，换一个结构就大面积 MISSING。

**修法**：加一层"结构识别"——先扫答卷的 sheet 名和表头，按语义映射到考点的取数坐标（"逐案责任" → 案件裁定，"准备金与现金" → 决策摘要的金额类）。

### P3 workflow 不能断点续跑

官方文档明确：workflow 跑完才返回，**不支持 pause 后继续**。

**修法**：19 节点拆成 3–4 个 workflow 调用（01–07 / 08–12 / 13 / 14–18），每批独立，失败只重跑一批，也方便按批控制成本。

### P4 13 作答节点太重

单节点 30 分钟、需要 100+ 轮，容易上下文膨胀。

**修法**：拆成 13a 事件重放 → 13b 排程 → 13c 资金 → 13d 打包，每个读上一步的 xlsx，不重算。

## 4. DSH 宿主审计结论（支撑上述设计）

1. **agent() 选项**：`tool-workflow` 的 agent 走 `AgentOptions` 子集；`reasoningEffort` 在宿主接口存在，但 workflow-ptc 白名单不包含，传入会被拒绝。`cwd/tools/path` 同理。
2. **cwd 与 AGENTS.md**：workflow 子代理复用父会话 cwd，自动加载工作目录 `AGENTS.md`，无 cwd 覆盖参数；因此 13 隔离不能靠工作目录。
3. **guest 运行时**：无 `fs/process/require`，`import("node:fs")` 报 `A dynamic import callback was not specified.`。所有真实文件操作只能由节点 agent/插件完成。
4. **会话事件**：workflow 记录 `tool-workflow/agent-start` / `agent-end`（childId/seq/label/phase）；插件可通过 `exec.agent.session` 定位 13 会话并读事件，作为 trace/审计数据源。
5. **结论**：编排脚本必须写成“调度 + 机器门禁解析 + 路由”，不能写成“文件系统脚本”。这是本卡唯一无法按字面实现的条目，已在 `nodeOptions` 注释、`workflow.js` 返回值和本交接记录。

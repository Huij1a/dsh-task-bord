# 目录说明

本文件承接从 `AGENTS.md` 移出的运行目录细节。它是给人看的说明，不会被 DSH 自动注入子代理上下文。

## 项目目录

```text
母版/
  prompts/                 20 份提示词（00_master + 00_spec + 01..18）
  workflow.js              当前 v006 主编排
  workflow_s2.js           历史 13→14 脚本，不再用于主流程
  judge.py                 v006 评分器
  manifest.json            母版受管文件 bytes/sha256 清单
tasks/<题ID>/
  prompts/                 开题时冻结的提示词副本
  workflow.js              开题时冻结的编排副本
  manifest.json            开题时冻结的母版清单
  artifacts/               00_spec..18_submit 各节点产物
插件/dsh-plugin-authoring/  开题、状态、脚本、会话轨迹和隔离审计插件
docs/                       进度、问题登记、审查、交接与历史文件
.dsh/skills/19step/         用户入口技能
```

`tasks/T-demo/` 是历史证据，冻结不改。v006 不再在任务目录内创建 `_answer_sandbox/`。

## 作答题包

13 的输入和交付放在项目目录外：

```text
D:\高经作答区\<taskId>\<runId>\
  input\                    最终题面 + 05 清单声明的 A 系列附件
  output\                   13 的交付文件
  host_trace.json           编排生成的宿主轨迹，13 不读
```

默认卷号为 `C01`；只有冻结版本不变且满足补卷条件时才另建 `C02` 题包。`input/` 不放考点、标答、rubric、门槛、B 系列、提示词、manifest 或项目路径信息。

任务侧保留评分与归档证据：

```text
tasks/<题ID>/artifacts/
  13_answer/<runId>/        14 从 output 原子归档的答卷与 隔离审计.json
  14_score/<runId>/评分.json
  14_score/补卷判定.json
  14_score/汇总.json
```

`judge.py --copy-to` 只写当前 `artifacts/13_answer/<runId>/`；复制前编排只清理该卷目录。

## 历史文件

- `docs/历史/rubric.json`：无运行时引用的旧根 rubric，仅作历史参考。各题使用的 rubric 始终是 `artifacts/11_rubric/rubric.json`。
- `母版/workflow_s2.js`：旧两节点脚本，保留用于追溯，不得作为 v006 A/B/C/D 主流程。

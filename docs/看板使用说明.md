# 任务看板使用说明

## 概述

`dsh-plugin-authoring` 是一个通用的任务看板 + 工作流画布插件。它不绑定出题场景，只依赖一套标准目录约定：`tasks/<任务ID>/manifest.json` + `artifacts/<节点>/_gate.json`。

**核心功能**：

1. 四栏看板 —— 任务按状态自动归档
2. 工作流画布 —— React Flow 按节点执行状态渲染
3. 会话跳转 —— 点击节点打开对应子代理会话，可直接继续对话

## 安装

### 1. 构建插件

```bash
cd 插件/dsh-plugin-authoring
pnpm install
pnpm run build
```

`pnpm run build` 会先由 `client.css` 生成 `styles.gen.js`，再用 esbuild 把 `client.jsx` 打成 lazy-CJS bundle（外层包 `window.__ModuleLoader__.load({ id, factory })`）。

### 2. 挂到 DSH profile

在 `C:\Users\Administrator\.dsh\profiles\desktop\package.json` 的 `dependencies` 里加软链依赖：

```json
"dsh-plugin-authoring": "link:D:/高经出题流水线/插件/dsh-plugin-authoring"
```

再在 profile 目录执行 `pnpm install`。**必须用 `link:`**：`file:` 是硬拷贝，改源码不会生效。

### 3. 注册插件

`C:\Users\Administrator\.dsh\profiles\desktop\cordis.patch.yml`：

```yaml
- insert:
  - name: dsh-plugin-authoring
    config:
      root: D:\高经出题流水线
      templateDir: 母版
      maxTasks: 200
```

DSH 的 `include:hmr` 会监听该文件并热重载插件，一般不需要重启。重载后界面会回到对话页，点侧边栏「任务看板」即可。

## 使用

### 四栏看板

侧边栏点「任务看板」：

- **草稿** —— 还没有任何节点启动
- **正在跑** —— 已有节点启动、尚未全部完成
- **已完成** —— 全部节点通过
- **异常中断** —— 有节点失败

每张卡片显示任务号、行业、进度条和 `x/20 节点`。

### 工作流画布

点任务卡片进入画布：20 个节点按 5×4 蛇形排列，连线按执行顺序串联。

- 灰色 = 待执行
- 蓝色（边框带呼吸动画）= 运行中
- 绿色 = 已通过
- 红色 = 失败

画布支持拖动、缩放、框选和 fitView 自动适配。

### 会话跳转

点画布上的节点：插件会先打开该节点所属的 workflow 父会话（使其上线），再切到对应子代理会话，模式 `continuable`，底部输入框可直接发消息。

节点还没执行过时，会提示「还没有运行记录」。

## 数据格式

### tasks/<任务ID>/manifest.json

```json
{
  "task": "T-20261106-03",
  "industry": "金融服务/银行、支付与消费金融",
  "spec": "…",
  "version": "v008",
  "template_version": "v008",
  "template_sha": "…",
  "frozen_at": "2026-11-06T08:00:00.000Z",
  "files": []
}
```

### artifacts/<节点>/_gate.json

节点执行后由节点自己写入（workflow 脚本本身不落盘）：

```json
{
  "summary": "节点摘要",
  "artifacts": ["…"],
  "conditions": { "条件名": true },
  "file_conclusion": "…",
  "reply_conclusion": "…",
  "extra": {}
}
```

判定规则：`conditions` 全部为 `true` → 已通过；有 `false` → 失败。没有 `_gate.json` 时才回退到会话事件流里的 `agent-end` 结果。

### 会话映射（自动）

不需要写任何 `_session.json`。看板每次刷新时扫描 `~/.dsh/sessions/` 下所有 `session.v4.jsonl.zstd`：

1. 用第一帧的 `header.cwd` 过滤出本项目目录的会话
2. 找 `tool/call` 且 `name === "workflow"` 的调用，从其 `arguments.args.taskDir` 解析出任务 ID，与紧随其后的 `tool-workflow/run-start` 按顺序配对，得到 `runId → taskId`
3. 找该 `runId` 下的 `tool-workflow/agent-start` 事件，`label` 形如 `deepseek-v4.1-flash/max | 01_src`，取 `" | "` 后的节点名，得到 `node → childId`
4. 点节点时用 `{ parentSessionId, childSessionId, mode: "continuable" }` 调 `ctx.uiWorkspace.openSession`

重试与返修（`01_src retry1`、`01_src_repair_1`）按节点名前缀识别，取最后一次尝试。

## 故障排查

### 看板不显示任务

- 确认 `tasks/` 下有任务目录且含 `manifest.json`
- 确认配置的 `root` 是任务目录的父目录

### 看板一直显示旧状态

`/api/authoring/board` 对 `board-state.js` 做了按 mtime 的缓存穿透；如果仍是旧数据，检查 `index.js` 里 handler 是否是最新版本，并 touch 一下 `cordis.patch.yml` 触发重载。

### 点节点提示「还没有运行记录」

该节点在当前项目里没有 `agent-start` 事件：可能还没跑过，或跑的会话不在 `~/.dsh/sessions/` 下。

### 子代理会话只读

必须先打开父会话再打开子代理。插件已经做了预加载（先 `openSession(parentSessionId)`，150ms 后 `openSession(child)`）；若仍只读，通常表示父会话文件不存在。

### 插件未加载 / 客户端崩溃

- `Renderer recovery exhausted: web boot: 1 entry did not activate` → 检查 `client.js` 是否是 `window.__ModuleLoader__.load({ id: "dsh-plugin-authoring", factory })` 的 CJS 包装，不能是普通 ESM
- `ERR_MODULE_NOT_FOUND: Cannot find package 'dsh-plugin-authoring'` → profile `package.json` 没加依赖，或 `pnpm install` 没跑
- 日志：`C:\Users\Administrator\.dsh\logs\desktop-next.log`

## 扩展

- 改状态判定：`插件/dsh-plugin-authoring/board-state.js`
- 改画布布局/节点样式：`插件/dsh-plugin-authoring/client.jsx` 的 `buildFlowGraph` 与 `FlowNode`
- 改配色：`插件/dsh-plugin-authoring/client.css`（全部使用 DSH `--dsw-alias-*` 设计令牌）

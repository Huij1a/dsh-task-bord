# 任务看板使用说明

## 概述

这是一个通用的任务看板插件，用于可视化多节点 workflow 的执行状态。

**核心功能**：
1. 四栏看板 - 任务按状态自动分类
2. 工作流画布 - React Flow 可视化节点执行状态
3. 会话跳转 - 点击节点打开子代理会话

## 安装

### 1. 构建插件

```bash
cd 插件/dsh-plugin-authoring
pnpm install
pnpm run build
```

### 2. 安装到 DSH profile

```bash
cd "C:\Users\Administrator\.dsh\profiles\desktop"
pnpm add "file:D:/你的项目目录/插件/dsh-plugin-authoring"
```

### 3. 配置插件

编辑 `cordis.patch.yml`：

```yaml
- insert:
  - name: dsh-plugin-authoring
    config:
      root: D:\你的项目目录
      templateDir: 母版
      maxTasks: 200
```

### 4. 重启 DSH

## 使用

### 四栏看板

点击侧边栏"任务看板"按钮，看板显示所有任务：

- **草稿** - 待处理/未开始的任务
- **正在跑** - 有节点正在运行的任务
- **已完成** - 所有节点都通过的任务
- **异常中断** - 有节点失败或未自动流转的任务

### 工作流画布

点击任务卡片打开工作流画布：

- 节点按网格布局，自动生成连线
- 节点颜色表示状态：
  - 灰色 - pending（未执行）
  - 蓝色 - running（运行中）
  - 绿色 - passed（已通过）
  - 红色 - failed（失败）
- running 状态的连线带动画效果
- 支持缩放、平移和自动适配视口

### 会话跳转

点击工作流画布中的节点：

- 如果节点已执行且记录了会话 ID，会打开子代理会话
- 支持 `continuable` 模式，可继续与子代理对话
- 节点未执行时会提示"会话 ID 未找到"

## 数据格式

看板通过读取任务目录的标准化文件结构来展示状态：

### manifest.json（必需）

```json
{
  "taskId": "task-001",
  "title": "任务标题",
  "description": "任务描述",
  "industry": "分类标签"
}
```

### _gate.json（必需）

每个节点执行后写入 `artifacts/<节点>/_gate.json`：

```json
{
  "ok": true,
  "pass": true,
  "failures": [],
  "summary": "节点摘要"
}
```

### _session.json（可选）

如果需要会话跳转功能，写入 `artifacts/<节点>/_session.json`：

```json
{
  "childSessionId": "会话ID",
  "parentSessionId": "父会话ID",
  "timestamp": "2026-11-06T08:00:00Z"
}
```

## 会话 ID 记录

### 方案 A：在 workflow 中记录（推荐）

修改 workflow 脚本，在每个节点执行后写入 `_session.json`。

由于 DSH workflow 的 `agent()` 函数不直接返回会话 ID，可以采用：

1. **让子代理自己记录** - 在节点提示词中添加指令，让子代理完成工作后调用插件工具记录会话 ID
2. **从父会话解析** - 解析 workflow 父会话文件，提取每个节点的子会话 ID

### 方案 B：暂不记录会话 ID

看板的基础功能（四栏分类、工作流可视化）已完全可用，会话 ID 记录是可选增强。

未记录会话 ID 时，点击节点会提示"会话 ID 未找到"。

## 故障排查

### 看板不显示任务

1. 确认 `tasks/` 目录下有任务目录
2. 确认任务目录包含 `manifest.json`
3. 确认至少有一个节点生成了 `_gate.json`

### 节点点击无反应

1. 确认节点已执行（有 `_gate.json`）
2. 确认 workflow 记录了会话 ID（有 `_session.json`）
3. 打开浏览器控制台查看错误日志

### 插件未加载

1. 确认 `cordis.patch.yml` 配置正确
2. 确认 `package.json` 中有插件依赖
3. 重启 DSH 并检查日志

## 扩展

### 自定义节点配置

在 `cordis.patch.yml` 中配置节点列表：

```yaml
- insert:
  - name: dsh-plugin-authoring
    config:
      root: D:\你的项目目录
      nodes:
        - stage_01
        - stage_02
        - stage_03
```

### 自定义看板分栏逻辑

修改 `插件/dsh-plugin-authoring/board-state.js` 的状态判断逻辑。

### 自定义节点渲染

修改 `插件/dsh-plugin-authoring/client.jsx` 的 `buildFlowGraph` 函数。

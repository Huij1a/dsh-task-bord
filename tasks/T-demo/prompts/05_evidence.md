# 05 证据链

## 任务

把选定的决定拆成"难点清单"，再据此列出附件清单。这是整条流水线的核心。

## 难点清单（一行一个难点，8–15 行）

| 列 | 填写要求 |
|---|---|
| 难点ID | M01… |
| 材料位置 | 落在哪份附件的哪条记录/哪个字段 |
| 判定依据 | 附件里哪条规则/字段语义决定对错 |
| 正确结果 | 具体数或结论 |
| 顺手的错法 | 模型最可能怎么错 |
| 错误结果 | 错法会得出什么数 |
| 对应考点 | 先留空，11 填 |
| 下游影响 | 错了会连带错哪些数 |
| 独立核对方式 | 怎么另算一遍 |

## 难点类型（至少覆盖 4 类）

1. 证据冲突：正式件 vs 草稿、已生效 vs 未生效、签发优先于会议纪要
2. 口径不同：含税/不含税、下单/实付、批次/单客
3. 状态与时点：待批≠批了、开票≠到账、测试没跑≠通过
4. 规则组合：同一对象命中多条规则，优先级随组合变化
5. 无解：所有候选都违反硬约束，正确答案是"不能继续"
6. 看似有问题其实没问题：字段按规定留空、条款按通用执行
7. 显著性反转：最显眼的材料是错的，真答案在不起眼处

## 附件清单

每份附件写：文件名、文种、谁在什么时点为了什么产生、承载哪个判断、缺它会少什么判断、是否含解法提示、是否含预填成果。

## 输出

- `artifacts/05_evidence/难点清单.csv`
- `artifacts/05_evidence/附件清单.csv`
- `artifacts/05_evidence/关系图.md`：对象/状态/时间/资金/权限/资源怎么互相约束

## 硬要求

- 抽走任何一份附件，必须有一项判断做不出来；做不到就删掉这份附件。
- 每个难点必须有"推翻错法的输入证据"，否则改成允许分支。
- 改一个关键事实，最终决定必须变化；不变化的记为局部问题。

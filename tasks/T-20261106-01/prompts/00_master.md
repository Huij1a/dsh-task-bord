# 00 主控任务书

你是本套流水线的调度者。`00_master.md` 只是调度契约，不是执行节点；实际流程由 **19 个执行节点**完成：`00_spec` + `01_src` 至 `18_submit`。每个节点是独立的 subagent 会话，互相看不到对话，只能通过 `artifacts/` 下的文件交接。

## 固定运行条件

- 所有节点固定使用模型 `deepseek-v4.1-flash`，推理等级固定为 `max`。
- 不得用规范内容、环境变量、其他批次或某个节点的建议覆盖该模型条件。
- 调度环境无法满足固定模型条件时立即停止，不得静默换模型继续。

## 适用范围

节点只描述**工作方式**（读什么、产出什么、怎么验），不预设行业、题型、平台和题面形态。

可变的：行业、岗位、任务类型、交付物数量与格式、是否涉及时点重放、规则复杂度、评分门槛。
不变的：每步只做一件事；节点间只传文件；判定节点不得修改上游，只写自己的结论文件；结构必须显式声明并被下游引用。

提示词里出现的字段、文件名、行业词和数值都只是形状示例。没有 `artifacts/00_spec/项目门槛.json` 的原文支持，不得把它们当成当前题目的默认值。

## 启动参数

工作流每次启动必须显式传入下列四个参数，缺一不可：

```json
{
  "taskDir": "<当前题目绝对路径>",
  "batch": "A | B | C | D | all",
  "specPath": "<当期项目规范文件或目录>",
  "industry": "<当期规范明确写出的行业；industry_tree 非 null 时须为其中节点>"
}
```

- `taskDir`：所有专家侧写入必须留在该目录内，上游产物也只从该目录读取。独立作答通过 host 管理的 `D:\高经作答区\<taskId>\<runId>` 外部题包隔离，不算任务目录内产物。外部只读输入是 `specPath`；不得把规范文件复制进任务目录冒充当期唯一真源。
- `batch`：只能取 `A`、`B`、`C`、`D` 或 `all`。取 `all` 时按 A → B → C → D 顺序连续执行；任一批硬门未通过就立即停止，不得跳过失败批次继续后续批次。
- `specPath`：`.md`、`.docx`、`.pdf` 文件，或递归包含这些格式的目录。
- `industry`：必须是当期规范明确写出的行业，不能只凭自由文本判断；`industry_tree` 非 `null` 时还必须是其中节点。

缺少任一参数时，调度器立即报错并停止当前批次。不得从目录名、样例、旧任务或上一版产物推断 `specPath` 或 `industry`。

## 顺序与批次

完整顺序：

`00_spec` → 01 素材采集 → 02 脱敏 → 03 材料初勘 → 04 选题定位 → 05 证据链 → 06 附件制造 → 07 元数据检查 → 08 题面 → 09 润色 → 10 难度诊断 → 11 考点与标答 → 12 冻结版本 → 13 独立作答 → 14 评分 → 15 全盘读卷 → 16 质检 → 17 打包交付 → 18 提交准备 → 18_rebuild_upload 上传包重建（编排执行，无独立提示词）

四批是人工检查点，必须按顺序执行：

| 批次 | 节点 | 进入下一批的硬条件 |
|---|---|---|
| A | `00_spec` + 01–07 | 00_spec 双产物、schema 与原文来源通过只读门禁，07 `pass: true` |
| B | 08–12 | 10 判定通过，11 `校验结论.json.pass=true`，12 成功冻结 |
| C | 13–16 | `artifacts/14_score/汇总.json.pass=true`，所选卷 `difficulty_pass=true`，16 质检 `pass: true` |
| D | `17_pack` → `18_submit` → `18_rebuild_upload`（编排执行，无独立提示词） | 17 包核对通过；18 字段映射 `pass=true`；上传包核对 `pass=true` |

上一批未通过时不得启动下一批。workflow 不支持暂停续跑，批次边界就是失败后的重跑边界；只有本文件失败路由明确允许时才重跑对应上游，未获允许必须停在判定报告交人决定，不从头伪造成功。

1. 12 不创建本地作答沙箱。12 只在 `artifacts/12_freeze/frozen/model_input/` 冻结最终题面和 A 系列附件，并在 `运行契约.json` 写清外部题包协议；专家侧文件不得进入该目录。
2. 编排在启动 13 前用冻结输入建立外部题包，固定为 `D:\高经作答区\<taskId>\<runId>\`；其中只能有 `input/`、空的 `output/`，13 结束后再增加 `host_trace.json`。`taskId` 是 `taskDir` 目录名，首卷 `runId=C01`。题包必须解析到 `taskDir` 之外，`input/` 必须与冻结清单逐文件 bytes/sha256 相同。
3. 14 必须在当前 workflow 子会话通过 `exec` 定位同批 `phase/label=13` 的作答子会话，并调用 host-owned `authoring_isolate`。会话证据缺失时，工具仍须尽力写出结构完整的 invalid 审计和 fail-closed trace；14 不得仅因 `pass=false`、`infrastructure_failure=true` 或结构化 `isolation_pass=false` 跳过 judge。只有审计与 trace 都无法生成、不可解析、身份无法绑定或缺少判断所需结构时才 fail closed。该工具在 judge 前生成外部题包根 `host_trace.json`，并在 judge 成功归档后把最终 `隔离审计.json` 固定写到 `taskDir/artifacts/13_answer/<runId>/隔离审计.json`；不得把审计写进题包。审计记录 `schema_version=1,task_id,run_id,model,pass,package_root,input_dir,output_dir,frozen_version,input_files[{path,bytes,sha256}],output_was_empty,brief_contains_no_task_dir,checks[{check_id,status,evidence}],violations,audited_at`，六项 check 固定为 `PACKAGE_OUTSIDE_TASK_DIR/RUN_ID_MATCH/INPUT_ALLOWLIST/INPUT_HASH/OUTPUT_EMPTY/BRIEF_NO_TASKDIR`；只有全部 `status=pass`、`violations=[]` 时才可 `pass=true`。13/14/16 不得改写审计。
4. 13 的 brief 变量只注入 `runId` 和 `answerPackage`。`runId` 必须匹配 `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`；`answerPackage` 是上述题包根。brief 不得出现 `taskDir`、项目根、冻结目录、artifacts 路径或其他专家侧路径。
5. 13 只读 `<answerPackage>/input/`，只写 `<answerPackage>/output/`；每卷独立会话、独立题包，不得续用上一卷上下文或输出。13 结束后由 host 在题包根生成 `host_trace.json`，至少含 `schema_version=1,model,started_at,ended_at,minutes,rounds,source="host"`；可选含 `task_id/run_id`，若写入则必须分别等于当前 `taskId/runId`。
6. 每卷执行一次 14；14 先用 `authoring_isolate` 完成隔离 precheck 并核验题包 trace，再对当前卷只调用一次 `judge.py --copy-to`，报告落盘后再 finalize 最终审计并核验。审计内容 `pass=false` 但文件结构完整时继续 judge 一次、finalize 该失败审计并触发首卷 invalid；只有审计/trace 无法生成或不可解析、身份无法绑定的基础设施故障才立即停人，不调用 judge、不补卷。归档目标固定为 `artifacts/13_answer/<runId>/`，由 judge 在受控路径内 staging、清旧内容并原子替换；14 只做路径预检，不手工预删，不合并旧文件。默认只跑 C01；14 完成首卷后必须生成 `artifacts/14_score/补卷判定.json`。补卷要求首卷输入 hash 与冻结清单未变，且至少一个条件成立：分数为有限数并落在 `[score_max-10, score_max]`；冻结 `any_of` 中 rounds 下界 `t` 满足 `t <= rounds <= t*1.2`；minutes 下界 `t` 满足 `t <= minutes <= t+5`；首卷 invalid（结构完整的隔离审计未通过、trace/runtime 无效、必需交付缺失、未自然完成或 judge fail closed）。没有对应 rounds/minutes 下界条目时该条件为 false，不得自造阈值；最多补唯一一次 C02，不得生成 C03。
7. 补卷不是返修，不得改 12 冻结版本、题面、附件、rubric 或门槛；C02 必须使用同一冻结输入新建题包。invalid 的 C01 原样保留，禁止覆盖，也禁止把无效答卷当低分卷参与比较。
8. 所有卷结束后，14 写 `汇总.json`；15 对 `run_ids` 中每一卷分别完整读卷并写分卷记录及汇总；16 必须核对每卷评分、隔离审计、host trace、补卷判定、最终选卷和两卷一致性。单卷时按唯一卷处理，双卷时仍逐卷留证。
9. C 批最终仍要求所选卷 `difficulty_pass=true` 且 14 汇总 `pass=true`、16 `pass=true`。最终难度不达标时停在汇总报告交人决定，14 不得自动返修；16 不通过时不得启动 17。

## 硬规则

1. **00_spec 强制前置**。每个节点开始前先确认 `artifacts/00_spec/项目门槛.json` 存在、可解析、必需键齐全、非空门槛的原文来源完整。任一条件不满足，立即停止，不得进入 01。
2. **从 01 起按职责读取项目门槛**。00_spec 负责产出；01–12、14–18 只读取与本节点相关的键，13 是隔离例外，只能读取题包 `<answerPackage>/input/`，不得读取项目门槛、题包根审计文件或其它专家侧产物。读取门槛必须同时检查 `extraction_status`：只有原值 `null` 且状态 `not_applicable` 才是规范未写、条件不适用；`unparseable` 或 `conflict` 一律阻断。`score_max`、`score_rule` 必须非 `null` 且为 `extracted`。不得用常识、示例或旧版补齐。
3. **每步只做本步**。不要替后面的步骤做决定，也不要把后面步骤的产物提前写出来。
4. **节点间只传文件**。下一步读上一步的产物路径，不要假设上下文还在。
5. **判定节点（07/10/14/16）不得修改上游，只写自己的结论文件**。
6. **行业不得越界**：题目行业必须与 `args.industry` 和项目门槛的 `industry` 一致；`industry_tree` 非 `null` 时还必须落在对应路径内。
7. **不得写死业务规则**：期次、分数、送分比例、任务类型、行业树、字段名、禁用项、截止时间和任何样例阈值只能来自项目门槛或当期交付规格。运营约束（如节点顺序、只读边界、文件名）可以固定，但不得冒充项目规范。
8. **所有完成必须有对应文件**；没有文件、文件为空、JSON 不可解析或判定未落盘，都不算完成。
